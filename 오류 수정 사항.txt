1) 문제 발견
ServerStat을 통해서 현재 서버의 상태를 관찰할 수 있게 코드를 작성하고 확인 했는데,
유저가 없음에도 CPU를 40%를 점유하고 있는 것을 확인하였음.

2) 문제 확인
 - 인게임 Update를 중단 시켰음에도 같은 CPU점유량을 확인
 - Network Thread와 Logid Thread를 차례로 OFF하여 LogicThread에 문제가 있음을 확인
 - Logic Thread가 Condition Variable의 Wait에 의존하여 Thread를 대기상태로 만들어주고 있는데,
   매번 깨어나는 것을 확인
 - 기상 조건 중 하나인 _isStart변수를 Start로 바꾸어주지 않아서 발생한 오류

3) 대처
 - 기존에 Start함수를 구현했음에도 호출해주지 않은 문제가 있었고,
   _isStart가 false임에도 계속 루프를 반복하여 CPU 자원을 소모하고 있었다.
 - 로직을 수정하여 GameGlobal에서 생성 후 Start()를 호출하고,
   _isStart를 반복탈출조건으로 추가하여 문제해결

4) 결과
 - 기존에 Logic Thread 1개 기준으로 프로세스가 CPU를 8%를 점유하고 있던 현상이
  -> 0% ~ 0.2% 가량으로 줄어들어 문제가 해결 된 것을 확인

1) 문제 발견
Server 에서 account를 생성할 때 id를 primary key로 만들었음에도
id를 admin' 으로 생성 요청하는 요청에 insert가 계속해서 성공하는 문제를 확인

2) 문제 확인
 - DB에서 id가 Primary Key로 생성되었는지 확인 -> primary key로 생성하였음
 - Query 요청 시 id 문자열이 'admin' 로 요청 되었는지 확인 -> admin으로 요청됨
 - DB 조회로 문자열 길이와 byte길이를 확인 -> 길이 255의 문자열 길이가 들어가고 있음을 확인

3) 대처
 - 코드상 DBParam에서 문자열을 넘거줄 때 문자열의 길이를 같이 넘겨주지 않아서 할당받은 name[255]가 전부 넘어가게 되어 문제가 발생하고 있었다.
   (admin + 쓰레기 값으로 255가 채워지고 있었음)
 - 로직을 수정하여 BindParam을 할 때 문자열의 길이를 같이 넘겨주어 필요한 부분만 저장될 수 있도록 함

4) 결과
 - 같은 id에 대해서 중복 검사가 정상적으로 처리되어 같은 id를 넣었을 때 중복을 정상적으로 반환
